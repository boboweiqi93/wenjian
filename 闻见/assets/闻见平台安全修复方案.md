## 1. 🔴 高优先级：添加安全响应头

### 1.1 当前状态

| 安全头 | 状态 | 值 |
|--------|------|----|
| X-XSS-Protection | ✅ 已配置 | `1; mode=block` |
| X-Frame-Options | ✅ 已配置 | `SAMEORIGIN` |
| Strict-Transport-Security | ✅ 已配置 | `max-age=31536000` |
| Content-Security-Policy | ❌ 缺失 | — |
| X-Content-Type-Options | ❌ 缺失 | — |
| Referrer-Policy | ❌ 缺失 | — |
| Permissions-Policy | ❌ 缺失 | — |

### 1.2 修复方案

#### 方案一：Nginx 配置

在 Nginx 的 `server` 块或 `location` 块中添加：

```nginx
# 阻止 MIME 类型嗅探攻击
add_header X-Content-Type-Options "nosniff" always;

# 控制 referrer 信息泄露范围
add_header Referrer-Policy "strict-origin-when-cross-origin" always;

# 限制浏览器功能 API 权限
add_header Permissions-Policy "camera=(), microphone=(), geolocation=(), payment=()" always;

# Content Security Policy
# 注意：'unsafe-inline' 对 React + Tailwind SPA 是必需的，否则页面崩溃
add_header Content-Security-Policy "
  default-src 'self';
  script-src 'self' 'unsafe-inline' https://assets.cdn.meoo.host;
  style-src 'self' 'unsafe-inline';
  font-src 'self' https://assets.cdn.meoo.host;
  img-src 'self' data:;
  connect-src 'self' https://wenjian.meoo.fun;
  frame-ancestors 'self';
  base-uri 'self';
" always;
```

**⚠️ 重要**：Nginx 不支持多行值，实际配置需要写为一行：

```nginx
add_header Content-Security-Policy "default-src 'self'; script-src 'self' 'unsafe-inline' https://assets.cdn.meoo.host; style-src 'self' 'unsafe-inline'; font-src 'self' https://assets.cdn.meoo.host; img-src 'self' data:; connect-src 'self' https://wenjian.meoo.fun; frame-ancestors 'self'; base-uri 'self';" always;
```

#### 方案二：如果使用 Cloudflare

在 Cloudflare Dashboard → **安全** → **HTTP 标头修改** 中添加：

| 名称 | 值 |
|------|----|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self' 'unsafe-inline' https://assets.cdn.meoo.host; style-src 'self' 'unsafe-inline'; font-src 'self' https://assets.cdn.meoo.host; img-src 'self' data:; connect-src 'self' https://wenjian.meoo.fun; frame-ancestors 'self'; base-uri 'self';` |
| `X-Content-Type-Options` | `nosniff` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | `camera=(), microphone=(), geolocation=(), payment=()` |

## 2. 🟡 中优先级：审核 Supabase RLS 策略

### 2.1 背景

前端 bundle.js 中暴露了 Supabase REST API 地址（`/sb-api/rest/v1/`），这是 SPA 架构的正常做法。数据的安全依赖于 **Row Level Security (RLS)**。

当前已捕获到的 API 调用模式：

```
GET /sb-api/rest/v1/users?select=*&username=eq.  ← 登录查询
GET /sb-api/rest/v1/courses?select=*&is_published=eq.true
GET /sb-api/rest/v1/user_courses?select=course_id&user_id=eq.xxx
```

### 2.2 需要检查的 RLS 策略

打开 Supabase Dashboard → **Authentication** → **Policies**，逐表检查：

#### `users` 表

```sql
-- ✅ 应配置的策略
-- 用户可以读取自己的数据
CREATE POLICY "users_read_own" ON users
  FOR SELECT USING (auth.uid() = id);

-- 管理员可以读取所有用户
CREATE POLICY "users_read_admin" ON users
  FOR SELECT USING (auth.jwt() ->> 'role' = 'admin');

-- 用户只能更新自己的数据
CREATE POLICY "users_update_own" ON users
  FOR UPDATE USING (auth.uid() = id);
```

#### `courses` 表

```sql
-- ✅ 应配置的策略
-- 任何人都可以读取已发布的课程
CREATE POLICY "courses_read_published" ON courses
  FOR SELECT USING (is_published = true);
```

#### `orders` 表

```sql
-- ✅ 应配置的策略
-- 用户只能看到自己的订单
CREATE POLICY "orders_read_own" ON orders
  FOR SELECT USING (auth.uid() = user_id);

-- 管理员可以查看所有订单
CREATE POLICY "orders_read_admin" ON orders
  FOR SELECT USING (auth.jwt() ->> 'role' = 'admin');
```

#### `user_courses` 表

```sql
-- ✅ 应配置的策略
-- 用户只能看到自己的课程关联
CREATE POLICY "user_courses_read_own" ON user_courses
  FOR SELECT USING (auth.uid() = user_id);
```

### 2.3 高危检查清单

| 检查项 | 可接受 |
|--------|--------|
| 用户能否查看其他用户的手机号/密码？ | ❌ 不可 |
| 未登录用户能否查看课程内容？ | ✅ 可（课程列表是公开的） |
| 用户能否修改其他用户的订单？ | ❌ 不可 |
| 用户能否越权访问管理后台数据？ | ❌ 不可 |

## 3. 🟡 中优先级：修复 React 表单状态绑定问题

### 3.1 问题描述

当前登录表单使用 `placeholder="手机号"` 的 `<input>` 组件，但该组件是受控组件（Controlled Component），直接设置 `input.value` 不会触发 React 的状态更新。这影响：

- 自动化测试场景
- 浏览器自动填充功能（autocomplete 虽已启用但可能不触发 onChange）
- 特殊登录场景

### 3.2 根本原因

输入字段被定义为受控组件：

```jsx
// 当前实现（简化）
<input
  type="text"
  placeholder="手机号"
  value={phone}           // ← 受控：value 由 React state 驱动
  onChange={handleChange} // ← 只有这个能更新 state
/>
```

### 3.3 修复方案

#### 方案 A（推荐）：使用 `react-hook-form` 或 `formik`

引入表单库自动处理状态绑定和验证：

```jsx
import { useForm } from 'react-hook-form';

function LoginForm() {
  const { register, handleSubmit } = useForm();

  const onSubmit = (data) => {
    // data = { phone: 'admin', password: 'admin123' }
    loginApi(data.phone, data.password);
  };

  return (
    <form onSubmit={handleSubmit(onSubmit)}>
      <input
        {...register('phone', { required: true })}
        placeholder="手机号"
        autoComplete="username"
      />
      <input
        type="password"
        {...register('password', { required: true })}
        placeholder="密码"
        autoComplete="current-password"
      />
      <button type="submit">进入</button>
    </form>
  );
}
```

#### 方案 B（轻量）：添加 `onBlur` 触发额外的状态同步

```jsx
// 在现有表单上增加 onBlur
<input
  value={phone}
  onChange={handleChange}
  onBlur={() => {
    // 强制从 DOM 读取最新值，处理自动填充
    const domValue = document.querySelector('input[placeholder="手机号"]').value;
    if (domValue !== phone) setPhone(domValue);
  }}
/>
```

### 4.2 管理后台增加确认弹窗

当前部分删除操作已有确认（`confirm` 弹窗），但可进一步优化：

```jsx
// 改为使用自定义模态确认，防误操作
function DeleteConfirmModal({ isOpen, onConfirm, onCancel, itemName }) {
  if (!isOpen) return null;
  return (
    <div className="fixed inset-0 bg-black/50 flex items-center justify-center z-50">
      <div className="bg-white rounded-lg p-6 max-w-sm">
        <h3>确认删除</h3>
        <p>确定要删除「{itemName}」吗？此操作不可撤销。</p>
        <div className="flex gap-3 mt-4">
          <button onClick={onCancel}>取消</button>
          <button onClick={onConfirm} className="bg-red-500 text-white">确认删除</button>
        </div>
      </div>
    </div>
  );
}
```

### 4.3 注册页增加验证码

当前注册仅需邀请码，建议增加：

- 图形验证码或滑块验证，防止机器人注册
- 注册频率限制（后端限流，如每分钟最多注册 3 次）

## 5. 快速排障指南

### 5.1 升级安全头后页面白屏

**原因**：CSP 策略过于严格，拦截了内联脚本或 CDN 资源。

**排查步骤**：

```bash
# 1. 打开 Chrome DevTools → Console，查看被拦截的资源
# 2. 常见的 CSP 报错：
#    - "Refused to execute inline script" → 需要在 script-src 加 'unsafe-inline'
#    - "Refused to load the script 'https://xxx'" → 需要把域名加到 script-src
#    - "Refused to apply inline style" → 需要在 style-src 加 'unsafe-inline'
# 3. 临时修复：先注释掉 CSP 头，逐步放宽策略
```

### 5.2 登录提示「用户名不存在」

**原因**：React 受控组件未捕获前端程序化设置的 `input.value`。

**解决**：
- 浏览器自动填充场景：用户点击「进入」按钮时手动从 DOM 读取输入值
- 自动化场景：使用 `nativeInputValueSetter` + `dispatchEvent(new Event('input', {bubbles: true}))` 触发 React 更新

### 5.3 Supabase RLS 配置后 API 返回 401

**原因**：匿名用户没有对应表的查询权限。

**解决**：
```sql
-- 允许匿名用户读取已发布的课程和文章
CREATE POLICY "courses_anon_read" ON courses
  FOR SELECT TO anon
  USING (is_published = true);

CREATE POLICY "articles_anon_read" ON articles
  FOR SELECT TO anon
  USING (is_published = true);
```
